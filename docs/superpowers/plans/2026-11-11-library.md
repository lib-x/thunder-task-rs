# Xunlei Client Implementation Plan

**Goal:** Implement `SPEC.md` without changing the existing module structure.
**Architecture:** Share response validation and configurable OAuth helpers between
the stateful client and the existing standalone auth functions. Keep wire models
and task serialization separate from transport.
**Tech Stack:** Rust, serde, reqwest/rustls, Tokio, qrcode 0.14.
**Spec:** `SPEC.md`.

## Constraints
- Caller supplies credentials; never invent credentials or signing logic.
- Preserve public auth functions; no blocking network/filesystem IO or production unwraps.
- Document public items and test without external network access.

## Tasks
- [x] Implement tolerant models, phase serde, create-body and filter serialization tests.
- [x] Repair auth serialization, QR rendering, error parsing, and configurable endpoints.
- [x] Implement configurable client, device login, session restoration and one-shot refresh.
- [x] Implement device fallback and task operations with correctly encoded paths/queries.
- [x] Run formatting, all-target Clippy with denied warnings, and tests; fix failures.

## Review Focus
- API errors inside HTTP 200 responses must not become successful empty objects.
- Retry only once on 401 and retain refresh tokens when rotation omits them.
- OAuth pending/slow-down must work for both success and failure HTTP statuses.
- Preserve unknown phase strings and device/task extension fields.
- Empty DELETE responses must succeed; IDs and query JSON must be URL encoded.

## Decisions
- Client methods use mutable access because refresh updates the borrowed session.
- List calls return one page; callers supply the filter page token explicitly.
- Optional task numeric fields retain JSON values to accept strings and numbers.
- Terminal output is limited to the required interactive stderr prompt.

## Verification
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, and `cargo test` pass.
- Fifteen unit tests use no network, covering serialization, device response shapes,
  session restoration, OAuth outcomes, unauthenticated access, and QR module fidelity.
- Public API documentation also passes rustdoc with missing documentation denied.
- Live API calls and real-account device authorization are not exercised.
